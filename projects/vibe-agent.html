Ph.D. Research

Vibe Agent

A metadata layer built into a repository’s file system that gives AI coding agents a shared architecture map of the codebase, so work done by separate agents over time stays consistent, reviewable, and testable.

The problem

AI coding agents are increasingly used the way contractors are used: one session makes a change, another session weeks later makes the next one, and no single agent holds the whole history. Each agent arrives with a long context window but no durable memory of the repository. It has to reconstruct the architecture from the code in front of it, every time, and as the codebase grows that reconstruction gets slower, more expensive, and less reliable. The practical failure mode is drift. Changes made by separate agents, each locally reasonable, pull the system’s structure in different directions, and the inconsistency only surfaces later, in review, in testing, or in production behavior nobody can trace back to a decision.

Longer context windows do not solve this on their own. A window is temporary and private to one session. What a multi-agent workflow lacks is a shared, persistent description of the system that lives with the code and that every agent can read before it writes.

The approach

Vibe Agent builds that description into the repository itself. It is a metadata layer in the repo’s file system that records the architecture as a map: the structure of the system, the dependencies between its parts, and the provenance of what is there. An external coding agent starting work in the repository reads the map first, so it begins from the same understanding of the codebase as every agent before it, instead of inferring the architecture from scratch.

Because the map lives in the file system alongside the code, it travels with the repository, is visible to human reviewers as well as agents, and gives changes a reference point: work can be checked against the recorded structure, which makes agent output easier to review and test. The research questions behind the project concern whether that kind of persistent, shared context measurably improves the consistency and quality of agent-produced software over time.

Status

Vibe Agent is the foundation of my dissertation research on vibe coding and software quality assurance at UMBC, and it is also my project for IS 809. The system is under active development in both a work setting and the research setting. The code repository is private while the research is in progress, so this page is an overview rather than a demo; publications and public artifacts will be linked here as the work reaches them.
